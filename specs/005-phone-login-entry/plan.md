# Implementation Plan: Phone Login Entry Screen

**Branch**: `005-phone-login-entry` | **Date**: 2026-10-07 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/005-phone-login-entry/spec.md`

## Summary

Connect the existing final onboarding page to a new `/login` route matching Figma node `5:63`,
adapted to Vazy branding. Reuse Expo Router's stack with `router.navigate`, the current safe-area
and status-bar patterns, a native keyboard-avoiding layout, and one controlled phone `TextInput`.
Keep Send Code and Sign Up present but non-actionable; add no authentication, permission, storage,
package, asset, or configuration work.

## Technical Context

**Language/Version**: TypeScript 6.0.3, React 19.2.3, React Native 0.86.3  
**Primary Dependencies**: Expo SDK 57, Expo Router 57, `expo-status-bar`, `react-native-safe-area-context`  
**Storage**: N/A; phone text exists only in component memory  
**Testing**: Expo lint, `tsc --noEmit`, Expo Doctor, Expo export, and the integrated device checks in `quickstart.md`  
**Target Platform**: iOS and Android portrait phones supported by Expo SDK 57  
**Project Type**: React Native mobile application  
**Performance Goals**: Login is fully visible within 300 milliseconds of the final onboarding action  
**Constraints**: Offline-capable; keyboard-safe; accessible; Vazy identity only; no false
authentication or sign-up action; no Firebase, SMS, location permission, consent persistence,
backend, MQTT, or hardware access; no dependency, asset-rule, or `.gitignore` change  
**Scale/Scope**: Modify one existing route and add one flat route; no new design asset is required
